Red Vault Privacy Policy

Effective date: February 15, 2026

Browser-only processing No external telemetry backend Aggregate metrics only

1. Overview

Red Vault Privacy is a browser extension that helps users protect sensitive information while using supported AI chat sites. The extension detects and pseudonymizes sensitive text in prompts and supported attachments before transmission, and restores readable context in-session using ephemeral mapping.

Supported sites currently include: chatgpt.com, chat.openai.com, and gemini.google.com.

2. Data We Process

To provide protection functionality, the extension may process user-entered or user-uploaded content on supported AI sites, including content that may contain personal or sensitive information.

Processed content types

  • Prompt text entered into supported AI chat compose fields.
  • Supported attachment text extracted locally in-browser (for supported file types).
  • Policy configuration data (managed and/or local rule settings).
  • Aggregate dashboard counters and telemetry metrics (counts only, no raw prompt bodies).

Examples of sensitive categories detected

  • Email addresses, phone numbers, account and financial identifiers.
  • Credential-like secrets (for example API keys/password-like patterns).
  • Custom enterprise keywords and patterns configured by policy.

3. How Data Is Used

  • Detect sensitive content in supported inputs.
  • Pseudonymize detected values before transmission to supported AI sites.
  • Restore readable context in-session using local ephemeral mapping.
  • Display aggregate operational metrics in the dashboard.

Red Vault Privacy is designed for a single purpose: reducing accidental exposure of sensitive information when users interact with supported AI chat platforms.

4. Storage, Retention, and Ephemeral Mapping

Ephemeral mapping model

  • PII mapping is tab/session scoped.
  • Mapping is cleared on tab close.
  • Mapping is cleared after inactivity timeout (about 30 minutes).
  • Mapping is cleared on browser/service-worker restart.

Persistent storage

  • No raw prompt bodies are intentionally persisted in extension storage.
  • No raw PII mapping tables are intentionally persisted as long-term stored data.
  • Aggregate metrics may be stored locally for dashboard/reporting purposes.
  • Policy settings (managed/local admin rules) may be stored locally per browser policy model.

5. Data Sharing and Transfers

  • Red Vault Privacy does not sell user data.
  • Red Vault Privacy does not transfer user data to external analytics or advertising platforms for unrelated purposes.
  • The extension does not rely on a dedicated Red Vault backend for core protection logic.

Note: content that a user chooses to send to third-party AI providers is subject to those providers' own terms and policies. Red Vault Privacy attempts to reduce raw sensitive exposure by pseudonymizing content before transmission.

6. Security Measures

  • Local processing model to minimize unnecessary transmission.
  • Fail-safe behavior when mapping continuity is unavailable (restore is skipped instead of incorrect restore).
  • Administrative policy controls and managed rule support where available.

Security boundary note: If an endpoint device is fully compromised, local protections may be bypassed by the attacker. Users should maintain endpoint security best practices.

7. Enterprise Policy Controls

In enterprise-managed environments, administrators may configure mandatory pseudonymization keywords and rules via browser managed storage/GPO channels. Managed rules are intended to be enforced as read-only controls in settings.

8. Children's Privacy

Red Vault Privacy is not directed to children under 13. We do not intentionally design the extension to collect children's personal data.
